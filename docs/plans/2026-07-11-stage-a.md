# Stage A Development Sandboxing Implementation Plan

**Goal:** Provide reusable local development isolation for a container-friendly web repository and a host-native Xcode repository without exposing host credentials or production mutation paths.

**Architecture:** A standalone Python CLI emits and executes constrained commands. OCI workloads use Apple `container` or Docker with one writable worktree mount and no inherited secrets. Xcode workloads remain on macOS with deterministic per-worktree build and optional simulator state under the user cache directory.

**Tech Stack:** Python standard library, Apple `container`, Docker fallback, Git, Xcode `simctl`.

## Acceptance criteria

- The CLI refuses a repository path that is not a Git worktree.
- Web plans mount only the selected worktree writable and do not inherit host environment variables or SSH.
- Web plans use a read-only root, tmpfs scratch space, and CPU/memory bounds.
- Production/deploy commands fail closed unless explicitly overridden.
- Xcode preparation creates deterministic isolated DerivedData/results/log directories and an environment file.
- Each iOS worktree can own and lease one persistent cloned simulator addressed by exact UDID.
- Lane cleanup shuts down or deletes only the owned simulator, never all host simulators.
- No company paths, project IDs, secrets, or production credentials appear in tracked public-core files.
- Unit tests cover safety gates and command construction.
- A real Apple-container smoke command and a host-native iOS preparation smoke are exercised locally.
